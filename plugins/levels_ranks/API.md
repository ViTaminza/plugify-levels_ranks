# levels_ranks — Plugify API design

The Levels Ranks core of the Pisex `cs2-lvl_ranks` Metamod:Source plugin, ported to a Plugify C++
plugin. This document is the contract between the plugin (`plugins/levels_ranks`) and the nine
modules that used to talk to it through the `ILRApi` interface of the original's `lvl_ranks.h`:
LR_ExStatsHits, LR_ExStatsWeapons, LR_ExStatsMaps, LR_ExStatsGeoIP, LR_UnusualKills, LR_FakeRanks,
LR_NameReward, LR_VIP_Multi and LR_GiveExp.

The design copies `plugins/admin_system` (see its `API.md`): the manifest is the API, `bin/plugify-gen`
generates the consumer headers, a hand-written wrapper restores the shape the modules were written
against, and an engine-free core carries everything that can be unit-tested.

custom target runs when the manifest is newer; a missing generator is ignored and the checked-in
headers are used).

## 2. Boundary rules

1. **Types.** Only `plg::string`, `plg::vector<plg::string>`, `plg::vector<int32_t>`, `int32`, `int64`,
   `bool`, and plain C function pointers cross the boundary. No `std::function`, no captures, no C++
   classes, no exceptions.
2. **`int&` out-parameters become `int32&` with `"ref": true`** (`OnLevelChangedPre`,
   `OnPlayerKilledPre`, `OnExpChangedPre` are the only ones) - the original's `int&` allowed a
   listener to rewrite the value, and the pair keeps that.
3. **`SourceMM::PluginId` registration becomes a Register/Unregister pair.** The original keyed its
   listeners by plugin id (one listener per plugin, re-registering replaced it); the Plugify pairs
   keep that behaviour. The wrapper hides it: a module calls `HookOnPlayerLoaded(cb)` /
   `UnhookOnPlayerLoaded()`.
4. **`GetDatabases()` becomes `GetDatabaseConfig()`.** A Plugify plugin cannot share another plugin's
   `Database` object (the worker thread and the callback queue belong to the owner), so the
   *settings* are exported and every module opens its own plgdb connection with
   `MakeDatabaseConfig(api.GetDatabaseConfig(), "lr.sqlite3")`. The table name is `GetTableName()`:
   the modules build `<name>_hits`, `<name>_weapons`, `<name>_maps`, `<name>_geoip` and
   `<name>_unusualkills` from it.
5. **`const char*` returns become `plg::string`.** The wrapper converts back to pointers that are as
   long-lived as the original's (`GetTableName()` is cached, the `steamid` handed to
   `OnPlayerLoaded`/`OnResetPlayerStats` is valid for the call, like `szAuth.c_str()` was).
6. **`IGameEvent*` becomes an `int64` handle.** Plugify cannot move an engine pointer under its own
   type checking, so the two kill hooks pass the s2sdk event handle as `int64`; the wrapper rebuilds
   the `pisex::IGameEvent` the modules read, valid for the duration of the callback (the same
   guarantee the original's pointer had). The modules' `event->GetInt("attacker")`,
   `GetString("weapon")`, `GetBool("headshot")` keep working; `event->GetPlayerController(...)`
   (a raw `CCSPlayerController*`) must become `pisex::g_pPlayers->GetControllerEntity(slot)` /
   `GetPawnEntity(slot)` on the ported side.
7. **`PrintToChat(slot, fmt, ...)` loses its varargs.** The export takes an already formatted
   string and prepends the `Prefix` phrase; `lr_api.hpp` keeps the printf-style signature and
   formats on the caller side, so ported call sites do not change.
8. **No exceptions** escape into the engine: every trampoline of the wrapper and every exported
   function catches (`catch (...)` + log).
9. **No blocking statements** on the game thread: every query is queued on plgdb's worker and its
   callback runs from `Poll()` inside `OnPluginUpdate`. `CreateSchema()` is the only blocking
   statement (plugin start).

## 5. Using the API from a module

Include paths (module `CMakeLists.txt`):

```cmake
target_include_directories(my_module SYSTEM PRIVATE
        "${CMAKE_SOURCE_DIR}/plugins/levels_ranks/include"                            # lr_api.hpp
        "${CMAKE_SOURCE_DIR}/plugins/levels_ranks/include/external/plugify/include"   # generated
        "${CMAKE_SOURCE_DIR}/sdk/include")
target_sources(my_module PRIVATE
        "${CMAKE_SOURCE_DIR}/plugins/levels_ranks/include/external/plugify/include/levels_ranks/levels_ranks.cpp")
# ... or link the object library the plugin defines:
target_sources(my_module PRIVATE $<TARGET_OBJECTS:lr_bindings>)
```

Porting recipe:

```cpp
// before (Metamod)
#include "include/lvl_ranks.h"
ILRApi* g_pLRCore;
g_pLRCore = (ILRApi*)g_SMAPI->MetaFactory(LR_INTERFACE, &ret, NULL);
g_pLRCore->HookOnPlayerLoaded(g_PLID, OnPlayerLoadedHook);
g_pLRCore->GetDatabases()->Query(...);

// after (Plugify)
#include <lr_api.hpp>
using namespace levels_ranks;                      // the LR_*/ST_* constants
levels_ranks::LrApi* g_pLRCore = &levels_ranks::LrApi::Get();
g_pLRCore->HookOnPlayerLoaded(OnPlayerLoadedHook); // the plugin id argument is gone
auto connection = plgdb::Database::Create(MakeDatabaseConfig(g_pLRCore->GetDatabaseConfig(), "lr.sqlite3"));
const char* table = g_pLRCore->GetTableName();     // "lvl_base"
```

Everything else keeps its original spelling: `g_pLRCore->GetClientInfo(i, ST_KILLS)`,
`g_pLRCore->CheckCountPlayers()`, `g_pLRCore->GetSettingsValue(LR_DB_SaveDataPlayer_Mode)`,
`g_pLRCore->ChangeClientValue(i, exp)`, `g_pLRCore->PrintToChat(i, phrase, args...)`,
`g_pLRCore->GetRankExp()`, `HookOnCoreIsReady`, `HookOnPlayerKilledPre`, `HookOnPlayerLoaded`,
`HookOnResetPlayerStats`, `HookOnDatabaseCleanup`, `HookOnPlayerPosInTop`, `HookOnExpChangedPre/Post`,
`HookOnLevelChangedPre/Post`.

Lifetime rules of the returned pointers (identical to the original's): `GetTableName()` points into
the wrapper's cache and stays valid until the next table-name query (the original handed out
`g_sTableName`, which never changed); the `steamid` handed to `OnPlayerLoaded`/`OnResetPlayerStats`
and the `IGameEvent*` of the kill hooks are valid for the duration of the callback; everything else
is returned by value.

Callbacks must not throw (the trampolines catch and log through `plg::Log`), and menu/pisexcompat
state must not be re-entered from inside them (see the pisexcompat notes).

## 7. The engine-free core (`lr_core`)

`lr_core` is a static library (plgdb only, no s2sdk, no Plugify types) so the whole
settings/rank/statistics logic is unit-testable:

* **`Settings` + `LoadSettings(ConfigView&)`** — the `settings.ini` model with the semantics and the
  defaults of the original's `LoadConfig()`: `lr_table` (default `lvl_base`), `lr_plugin_title`,
  the 22 `MainSettings` values, the `Funded_System` / `Rating_Extended` / `Rating_Simple` blocks
  (selected by `lr_type_statistics`), the `lr_killcoeff` clamp to `[0.5, 1.5]` (stored ×100),
  `Special_Bonuses` (`lr_bonus_1..10`) and the `Ranks` block (name → experience, in file order).
  The plugin fills it from the real file with the pisexcompat KV parser (`lr_keyvalues.hpp`); the
  tests drive the same code with a literal tree.
* **Inherited quirks, kept on purpose** (marked `PARITY:` in the code):
  * `lr_resetmystats_cooldown` is read off the *root* node, where a key nested inside `MainSettings`
    is not found — the cooldown is always the default `86400`.
  * the core's own macro block names the "show level up/down message" slots 6 and 7, i.e. the same
    slots the interface calls `LR_ShowAllLevelUpMessage`/`LR_ShowAllLevelDownMessage`: the later read
    (`lr_show_levelup_message`) wins, so both the personal and the broadcast message are driven by
    it, and the interface's `LR_ShowLevelUpMessage` (22) / `LR_ShowLevelDownMessage` (23) always read
    `0` (they were never written in the original either).
  * `RankForExp` is the original's `while (--iRank && g_hRankExp[iRank-1] > iExp)` loop, including
    rank `0` for an experience below the first threshold.
  * `ChangeClientValue` assigns the *clamped* delta to the round/session counters when it floors.
  * the play-time column is recomputed from a back-dated in-memory value
    (`ST_PLAYTIME = now - accumulated`), so a save stores `accumulated + session`.
  * `NotifClient` (used by the kill/round/bomb/hostage handlers) returns "the status passed", not
    "an amount was applied"; the handlers keep testing that exact value.
* **Database** — one table, the columns of the original (`steam` PK, `name`, `value`, `rank`,
  `kills`, `deaths`, `shoots`, `hits`, `headshots`, `assists`, `round_win`, `round_lose`, `playtime`,
  `lastconnect`, `online`), `CREATE TABLE IF NOT EXISTS` plus the MySQL `ADD COLUMN online` /
  `SET NAMES` / `SET CHARSET` / charset + `name varchar(128)` ALTERs of the connect callback
  (skipped for the SQLite fallback, which has no charsets), the count query, the `online = 0`
  startup reset and `OnCleanDB`'s `lastconnect = 0` update for players gone for `lr_cleandb_days`.
* **Player paths** — `LoadOrCreatePlayer` (the 13-column SELECT with the two place-in-top
  sub-queries, or the INSERT of a fresh row and `g_iDBCountPlayers++`), `SavePlayer` (the REPLACE
  plus the place-in-top refresh, or the disconnect variant that clears the slot and sets
  `online = 0`), `GiveExp` (`NotifClient`), `ChangeClientValue`, `CheckRank`, `ResetPlayerStats`,
  `CleanupData` (`mm_lvl_reset`), `LoadTopPlayers`, `CleanDatabase`, `InitializedSlots`.
* **Engine boundary** — the core never asks the engine anything: the plugin supplies
  `findPlayerName` (the original's `GetClientConVarValue(slot, "name")`), validates the player
  (`CheckStatus`) and passes the slot in; everything else comes back through the hooks
  (`onCoreReady`, `onPlayerLoaded`, `onLevelChangedPre/Post`, `onPlayerKilledPre/Post`,
  `onPlayerPosInTop`, `onExpChangedPre/Post`, `onResetPlayerStats`, `onDatabaseCleanup`,
  `onLevelMessage`, `onExpMessage`, `onError`).

Threading: `Query()` never blocks (plgdb worker thread), all callbacks run on the game thread from
`Poll()`, `CreateSchema()` is the only blocking statement. Results that land after the core was
destroyed are dropped (a lifetime token guards every callback).

### Compatibility notes (deliberate deviations)

1. **A Rating_Extended kill by an attacker with 0 experience** divided by zero in the original
   (undefined behaviour); the port treats the ratio as 1 (5 experience before the minimum).
2. **SQLite fallback.** The original was MySQL-only. A missing `levels_ranks` entry in
   `databases.cfg` now falls back to a local SQLite file instead of unloading the plugin, and the
   charset/ALTER statements are MySQL-only. The table layout, the statements and the values are
   otherwise identical, so one MySQL database can be shared with the Metamod server.
3. **A missing `settings.ini` block is logged, not fatal.** The original ran
   `meta unload <id>`; a `Failed` result of `OnPluginStart` would stop *every* Plugify plugin, so the
   port keeps the defaults of the missing block (see the porting rules).
4. **Values are bound, not interpolated.** `plgdb` binds `?` placeholders; the original built SQL
   strings and escaped the player name with `IMySQLConnection::Escape`. The database sees the same
   values.
5. **`GetDatabaseConfig()` instead of a shared connection** (rule 4 above) means a module that ran
   queries through the core's connection now opens its own - the connection settings are identical.
6. The in-memory `g_Settings` array is 24 entries; the original's `int g_Settings[22]` wrote two
   elements past its end for the slots 22/23 above (harmless there because they were never read).

## 8. The engine side

`src/plugin.cpp` (lifecycle, settings/phrases/database, s2sdk listeners, the game events, the
cookies, the messages and the exports), `src/commands.cpp` (the commands) and `src/menus.cpp` (the
menu tree) port `levels_ranks.cpp` onto `lr_core` + pisexcompat.

Flow: `OnPluginStart` reads `settings.ini`, both phrase files and opens the database from the
`levels_ranks` section of `databases.cfg` (SQLite fallback when the entry is missing), creates the
schema, **fails soft** when that fails, registers the s2sdk listeners, the commands and the twelve
event hooks and starts the one-second timer. `OnPluginUpdate` pumps `pisex::Poll()` (deferred
startup callbacks, timers, queued menu changes) and `db->Poll()` (query results).

* **Player loading.** The original hooked `IServerGameClients::ClientPutInServer`. s2sdk's
  `OnClientAuthenticated` is not reliable (see `perm_connector`), so the plugin registers it *and*
  reconciles every connected, authenticated player without a loaded row once per second - the same
  `LoadOrCreatePlayer` path, so a late load or a missed event cannot leave a player without
  statistics.
* **Saving.** A disconnect (`OnClientDisconnect_Post`) saves the row and sets `online = 0`. The
  original's `CheckStatus()` also required a live pawn during the disconnect; the port saves
  whenever the row is loaded (the counters are what has to reach the database).
* **Events** (pisexcompat pre hooks, same names and bodies as the original): `player_death`,
  `bomb_planted`, `bomb_defused`, `bomb_dropped`, `bomb_pickup`, `round_start`, `round_end`,
  `round_mvp`, `hostage_killed`, `hostage_rescued`, `weapon_fire`, `player_hurt`.
* **The statistics gate** (`CheckAllowStatistic`) runs on `round_start`, on every player connect and
  once per second: fewer than `lr_minplayers_count` players with a team and a pawn, or a warmup
  period with `lr_block_warmup = 1`, switches the counting off and drives the two
  `RoundStartMessageRanks` / `RoundStartCheckCount` messages. The warmup flag is
  `g_pGameRules->m_bWarmupPeriod` of the original: s2sdk's `GetGameRules()` hands out the
  `CCSGameRules` **object** (not the proxy entity `GetGameRulesProxy()` returns) and the field is
  read at its resolved schema offset of that pointer; when the field is missing the plugin logs it
  once and treats the round as rated.
* **Cookies.** The original's `GetClientCookie`/`SetClientCookie` (`LR.<name>`) become the official
  permissions cookies with the *same* names - `LR.ResetMyStatsCooldown` is the only one the core
  uses. Without the permissions plugin they live in an in-memory session store (the original fell
  back to `addons/data/lr_data.ini`; no file is written by the port).
* **Commands** (same names, permissions and texts as the original):

  | Kind | Names |
  | --- | --- |
  | console | `mm_lvl_give_admin <userid\|steamid>` (grants `g_bAdminAccess`, the only way the original granted the admin menu), `mm_lvl_reset <all\|exp\|stats>` |
  | console + chat | `mm_lvl`/`sm_lvl` + `!lvl`/`lvl`/`!дмд`/`дмд` (main menu), `mm_rank`/`sm_rank` + `!rank`/`rank`/`!кфтл`/`кфтл` (rank report), `mm_session`/`sm_session` + `!session`/`session`/`!ыуыышщт`/`ыуыышщт` (the original registered a no-op handler), `mm_toptime`/`sm_toptime` + `!toptime`/… (play-time top), `mm_top`/`sm_top` + `!top`/… (experience top) |
  | menu | main menu (`OnLRMenu`), my stats (+ session + reset with the cooldown cookie), the two tops, the rank list, the admin menu (`ReloadAllConfigs`, give/take experience) |

* **Menus** are built with pisexcompat (`pisex::Menu`); item numbers 1..5 and the `7`-back cancel
  reason are the ones the original switched on, so the ported handlers keep their shape.
* **Configs and phrases** come from `<configs>/levels_ranks/{settings.ini,translations/*.phrases.txt}`
  through pisexcompat's path resolver, i.e. the original file names and layout.

Deviations of the engine side (all deliberate, the rest is parity):

1. `PrintToChat` from a module is pre-formatted (the varargs cannot cross the boundary); the core's
   own messages use the same phrase keys and the same order of arguments as the original.
2. `mm_lvl_give_admin` accepts the account id, the slot or the SteamID64 of a player, like the
   original; it prints to the server console (`[LR] Admin access granted` / `Player not found`).
3. `mm_lvl_reset` prints its result through the pisexcompat console printer instead of `Msg()`, and
   reloads every loaded player after the cleanup (the original called its `OnClientPutInServer` for
   each `bInitialized` slot).
4. The plugin never unloads itself (the original ran `meta unload`); every failure is logged and the
   plugin keeps running as a no-op.
